# Proposal

## Why

Сервер MCP і всі операції з RDL зараз працюють лише через Python та запускаються через `uvx`. Перенесення на Go дасть окремий виконуваний файл без вимоги встановлювати Python у користувача, водночас зберігши доступні інструменти й результати редагування звітів.

## What Changes

- Перенести всі 15 наявних MCP tools і логіку читання, перевірки та редагування RDL у Go.
- Використати офіційний Go SDK для MCP та його stdio transport замість власної реалізації JSON-RPC.
- Зберегти назви інструментів, аргументи, значення за замовчуванням, форму результатів і підтримку RDL 2016 та Tablix; відмінності протоколу, які запроваджує SDK, перевірити з MCP-клієнтом.
- **BREAKING**: після підтвердженої сумісності замінити запуск `uvx rdl-mcp` / PyPI-пакет на Go-бінарник; оновити інструкції, `server.json` і процес публікації. Старий Python-код залишити тільки на час порівняльних тестів і прибрати під час завершення міграції.
- Прямі Go-залежності обмежити погодженими користувачем MCP SDK і `github.com/dlclark/regexp2/v2@v2.8.0` для сумісності `field_pattern`; інші потребують окремого аппруву.

## Capabilities

### New Capabilities

- `rdl-mcp-server`: запуск Go MCP сервера через stdio, наявний каталог інструментів, обробка викликів і результати.
- `rdl-report-operations`: читання, валідація й зміна RDL з поведінкою, сумісною з поточним Python-сервером.

### Modified Capabilities

Немає: у репозиторії ще не було основних OpenSpec-специфікацій.

## Impact

Зачепить `rdl_mcp_server.py`, пакет `rdl_mcp/`, тести, `pyproject.toml`, `setup.py`, `README.md`, `CLAUDE.md`, `server.json` і workflows публікації. Прямими Go-залежностями плануються `github.com/modelcontextprotocol/go-sdk` та погоджений `github.com/dlclark/regexp2/v2@v2.8.0`; XML, файли, логування та збірка використовуватимуть стандартну бібліотеку Go. Користувачам доведеться змінити команду запуску MCP сервера.
