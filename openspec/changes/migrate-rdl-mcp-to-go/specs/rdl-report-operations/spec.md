# Spec Delta

## Purpose

Ця можливість надає роботу з файлами звітів RDL: читання структури, перевірку коректності та контрольоване редагування таблиць, датасетів і параметрів.

## ADDED Requirements

### Requirement: Читання структури RDL
Сервер SHALL читати RDL 2016 і повертати поточні структури результатів для опису звіту, датасетів, параметрів і колонок Tablix. Читання SHALL не змінювати файл.

#### Scenario: Опис звіту
- **WHEN** користувач викликає `describe_rdl_report`, `get_rdl_datasets`, `get_rdl_parameters` або `get_rdl_columns` для валідного RDL
- **THEN** кожен tool повертає той самий набір і типи полів, що відповідає Python-реалізації для цього файлу

#### Scenario: Фільтрація полів датасету
- **WHEN** `get_rdl_datasets` отримує `field_limit=-1` або `field_pattern`
- **THEN** список полів, його обмеження й прапорець `fields_truncated` відповідають поточній семантиці Python-сервера

### Requirement: Перевірка RDL
`validate_rdl` SHALL повертати поточну структуру `valid` та `issues` для перевірки XML, структури звіту й посилань на поля, не змінюючи файл.

#### Scenario: Пошкоджений XML
- **WHEN** користувач перевіряє невалідний XML
- **THEN** результат містить `valid=false` і опис причини в `issues`, а файл лишається незмінним

### Requirement: Редагування колонок Tablix
Сервер SHALL підтримувати оновлення заголовка, ширини й формату, додавання й видалення колонки з поточною індексацією, необов'язковими полями та поведінкою автоматичного коригування ширини сторінки.

#### Scenario: Додавання та видалення колонки
- **WHEN** користувач додає колонку і потім видаляє її за коректним індексом
- **THEN** результати обох викликів та структура збереженого RDL відповідають поточній Python-реалізації

#### Scenario: Неприпустимий індекс
- **WHEN** користувач передає індекс поза межами таблиці
- **THEN** tool повертає поточний формат відмови `success=false` з поясненням і не змінює файл

### Requirement: Редагування датасетів і параметрів
Сервер SHALL підтримувати `update_stored_procedure`, `add_dataset_field`, `remove_dataset_field`, `add_parameter` та `update_parameter` з поточними правилами пошуку, дублювання, повідомлень про результат і запису RDL.

#### Scenario: Зміна датасету
- **WHEN** користувач змінює процедуру або додає чи вилучає поле в наявному датасеті
- **THEN** наступне читання відображає цю зміну та повертає сумісну структуру відповіді

#### Scenario: Дубль параметра
- **WHEN** користувач додає параметр з наявним ім'ям
- **THEN** виклик повертає `success=false` з поясненням і не додає дубль у файл

### Requirement: Збереження документа й меж підтримки
Редагування SHALL зберігати валідний RDL 2016, потрібні простори імен, неторкнуті елементи звіту й підтримку поточних Tablix сценаріїв. Сервер SHALL не заявляти підтримку Matrix або Chart, якої немає в поточному продукті.

#### Scenario: Редагування звіту з іншими елементами
- **WHEN** tool змінює одну підтримувану частину RDL, що містить інші елементи або префікси просторів імен
- **THEN** змінена частина читається знову, документ лишається валідним, а нецільові елементи й простори імен зберігаються
